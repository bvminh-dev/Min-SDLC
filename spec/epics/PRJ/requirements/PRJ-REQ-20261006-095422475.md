## User story
Là tác nhân `system` (developer, CI và lệnh vận hành; không đăng nhập, `roles.md` R-01), tôi muốn một monorepo dựng được từ máy sạch, có CI chặn lỗi, lộ bí mật, phụ thuộc có lỗ hổng và vi phạm ranh giới module, để mọi epic sau viết code trên cùng một nền và không phá kiến trúc đã chốt.

## Quy tắc nghiệp vụ
- BR1: Một monorepo pnpm (ADR-002) gồm `apps/api` (NestJS) và `apps/web` (Next.js) tách riêng. Mã dùng chung đặt ở `packages/` chỉ khi có từ hai nơi dùng.
- BR2: Từ một bản clone sạch, `pnpm install --frozen-lockfile` rồi `pnpm dev` chạy được api và web trên máy dev với cơ sở dữ liệu local theo README; mục tiêu một developer mới làm xong trong 15 phút (mặc định, đo được).
- BR3: Ở thư mục gốc có đúng bốn lệnh chuẩn `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`; mỗi lệnh thoát mã khác 0 khi lỗi. CI chạy cả bốn trên mỗi pull request; pull request đỏ không merge được.
- BR4: Backend theo cấu trúc `apps/api/src/modules/<module>`, tên module theo bảng ánh xạ ở `spec/architecture.md` (platform, auth, user, catalog, ...). PRJ chỉ tạo module `platform` (config, DB, lỗi, log, audit, giới hạn tần suất, outbox, idempotency, job nền, guard). Module khác do epic của nó tạo. Mỗi module có một điểm vào công khai duy nhất (`index.ts`); import chéo module chỉ qua điểm vào đó.
- BR5: CI kiểm ranh giới (P7, SB-35): module A import module B thất bại nếu B không nằm trong cột Phụ thuộc của A ở `architecture.md`, hoặc nếu import vào file bên trong B thay vì điểm vào công khai. `platform` là mối quan tâm cắt ngang (`architecture.md`, A-01, ADR-012): mọi module được import điểm vào công khai của `platform` mà không khai PRJ ở cột Phụ thuộc. Guard dùng interface `SessionContext {user_id, role, email_verified}` do platform định nghĩa; AUTH cung cấp triển khai (đảo phụ thuộc), nên module khác không import `auth` để lấy phiên (AUTH-REQ-20261006-095515808). Bảng "Giao diện module" của `architecture.md` là hợp đồng gọi đồng bộ; đổi chữ ký phải chạy sdlc-impact (ADR-012).
- BR6: Quét bí mật chạy trước mỗi commit (hook) và trong CI (SB-15); quét lỗ hổng phụ thuộc chạy trên mỗi pull request và định kỳ mỗi tuần (SB-17); phát hiện mức `high` trở lên làm CI đỏ.
- BR7: Ghim công cụ: phiên bản Node qua `.nvmrc` và `engines`, pnpm qua `packageManager`; `pnpm-lock.yaml` được commit. [OPEN: số phiên bản Node cụ thể và công cụ test; mặc định theo mặc định của NestJS (Jest).]
- BR8: `.gitignore` chặn `.env*` (trừ `.env.example`), `node_modules`, thư mục build.
- BR9: Bước build không cần bí mật runtime nào và tạo cùng một artifact cho cả ba môi trường; khác biệt giữa môi trường chỉ nằm ở cấu hình (xem PRJ-REQ-20261006-095422735).
- BR10: Test tích hợp chạy trên PostgreSQL thật (container), không dùng SQLite hay giả lập CSDL (xem PRJ-REQ-20261006-095422563).
- BR11: CI kiểm module không đọc bảng của module khác (SB-35): truy cập model Prisma hoặc tên bảng trong SQL thô (`$queryRaw`) thuộc `prisma/schema/<module>.prisma` của module khác chỉ hợp lệ khi nằm trong chính module sở hữu bảng đó; module khác phải gọi giao diện ở `architecture.md`. Kèm kiểm lệch migration (BR3 của PRJ-REQ-20261006-095422563).

## Kịch bản
### Luồng chính
- **Given** developer mới có Node và pnpm đúng phiên bản đã ghim, và một PostgreSQL local theo README
- **When** chạy `pnpm install --frozen-lockfile` rồi `pnpm dev`
- **Then** api lắng nghe và `GET /api/v1/health` trả 200, web mở được, không cần sửa file nào ngoài tạo `.env` từ `.env.example`

### Luồng lỗi
- **Given** một pull request làm `package.json` và `pnpm-lock.yaml` không khớp
- **When** CI chạy `pnpm install --frozen-lockfile`
- **Then** bước cài đặt thất bại, pull request đỏ, không merge được

- **Given** module `catalog` import trực tiếp file bên trong module `order`, hoặc module `order` import module `payment` (không có trong Phụ thuộc của ORD)
- **When** CI chạy kiểm ranh giới module
- **Then** kiểm thất bại, thông báo nêu file, module nguồn, module đích và quy tắc bị vi phạm

- **Given** developer commit một tệp chứa chuỗi giống khóa bí mật (ví dụ khóa cổng thanh toán)
- **When** hook trước commit chạy
- **Then** commit bị chặn và thông báo nêu tệp, dòng; CI cũng đỏ nếu hook bị bỏ qua

### Ca biên
- **Given** một phụ thuộc đã merge hôm nay bị công bố lỗ hổng mức `high` vào tuần sau
- **When** quét định kỳ hàng tuần chạy
- **Then** quét báo lỗi mức `high` và CI định kỳ đỏ dù không có pull request mới

- **Given** pull request chỉ sửa tài liệu trong `spec/`
- **When** CI chạy
- **Then** bốn lệnh chuẩn vẫn chạy và qua; không có bước nào đòi bí mật runtime

- **Given** module mới `payment` được thêm với phụ thuộc `order` đúng như `architecture.md`
- **When** CI chạy kiểm ranh giới
- **Then** import `payment` tới điểm vào công khai của `order` qua, import ngược `order` tới `payment` thất bại (liên lạc ngược chiều chỉ bằng domain event)

- **Given** module `catalog` import điểm vào công khai của `platform` (ví dụ `AuditService`, `TransactionService`) mà cột Phụ thuộc của PRD là PRJ ngầm (không khai)
- **When** CI chạy kiểm ranh giới
- **Then** import qua; nhưng import file nội bộ của `platform` (không qua `index.ts`) thất bại

## Dữ liệu và sự kiện
- Entity đọc/ghi: không (PRJ không sở hữu entity, `spec/domain/entities.md`).
- Domain event phát ra: không.
- Epic khác bị chạm: mọi epic (cấu trúc thư mục, quy ước module). AUTH cung cấp triển khai `SessionContext` (AUTH-REQ-20261006-095515808).
