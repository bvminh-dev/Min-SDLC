## Các bước
- **Given** admin đăng nhập; nguồn `website` (`is_system` = true) có 300 đơn
- **When** admin gọi `PATCH` nguồn `website` với `{ "is_active": false }`
- **Then** 409 `order-source-protected`; `website` vẫn `is_active` = true; không audit
- **When** admin gọi `PATCH` nguồn `website` với `{ "name": "Cửa hàng trực tuyến", "position": 0 }`
- **Then** 200; tên đổi (đổi tên được); `code` vẫn `website`
- **When** chạy SQL thô trong CSDL test: `UPDATE order_sources SET code = 'web2' WHERE code = 'website'`, `UPDATE ... SET is_system = false`, `UPDATE ... SET is_active = false`, `DELETE FROM order_sources WHERE code = 'facebook'` (mỗi câu một lần)
- **Then** cả bốn bị CSDL từ chối (trigger chặn đổi `code` và `is_system`, CHECK `NOT is_system OR is_active`, trigger chặn DELETE); các đơn gắn `website` nguyên vẹn

## Dữ liệu và ghi chú
CSDL là lớp phòng thủ thứ hai (SB-45, SB-32). `facebook` đã có đơn nên DELETE còn bị `ON DELETE RESTRICT`; ca xóa một nguồn chưa gắn đơn cũng bị trigger chặn (lặp lại với `hotline` mới thêm, không đơn).
